# 字幕与学习层设计

> 日期：2026-10-28
> 代码：[Packages/LearningCore](../Packages/LearningCore)。这是本设计的核心模型和扩展协议，已经可以编译，12 个测试全部通过（Swift 6 严格并发，无警告）
> 相关文档：[技术选型](tech-stack.md)、[竞品调研](macos-player-research.md)

---

## 1. 设计目标

1. **英文字幕是整个产品的核心数据**：点词、循环、跟读、生词本、统计都建立在同一份结构化剧本上。
2. **以后加什么功能都不用改核心代码**：所有能力都通过「扩展点」接入，内置功能也走同样的扩展点。
3. **用户能自定义一切**：学习流程、快捷键、鼠标手势、字幕样式、遮挡规则全部是数据（JSON），不是写死的代码。
4. **和播放内核解耦**：学习层只要求播放器「能播一段区间」，底层用 AVPlayer 还是软解都不影响。
5. **低功耗**：字幕只在换句时刷新；查找当前句用二分查找；剧本处理是离线批处理，结果缓存。

## 2. 总体结构

```
          字幕来源 (SubtitleSource)
  Emby 字幕 · 内嵌轨 · 本地文件 · 图形字幕 OCR · Whisper ASR · 在线字幕库
                         │  SubtitleTrack（原始字幕，只读）
                         ▼
          剧本流水线 (TranscriptPipeline)
  断句 → 分词/词形还原 → 中英对齐 / 词级时间戳 → 翻译 → 打标签 → 应用用户编辑
                         │  Transcript（学习用剧本，带缓存）
         ┌───────────────┼──────────────────┬──────────────────┐
         ▼               ▼                  ▼                  ▼
   字幕渲染          交互层              学习程序执行器        查词服务
  显示层 + 主题    命令 + 手势/按键绑定   PlaybackDirector     LookupService
  + 遮挡策略        + 右键菜单            （逐句执行步骤）      （多来源并行）
         └───────────────┴─────────┬────────┴──────────────────┘
                                   ▼
                    学习事件 (EventBus) → 落库流水 → 统计 / 生词本 / FSRS 复习

  ExtensionRegistry：以上每一层的扩展点都在这里注册（内置功能和扩展一视同仁）
```

## 3. 数据模型：三层分离

| 层 | 类型 | 说明 |
|---|---|---|
| 原始字幕 | `SubtitleTrack` / `SubtitleCue` | 来自各种来源，**只读**，保留原样，方便随时重新生成剧本 |
| 学习剧本 | `Transcript` → `Sentence` → `Token` / `Span` | 流水线的产物，所有功能只读这一份 |
| 用户数据 | 收藏、生词、笔记、`TranscriptEdit` | 单独存储，用 `SentenceAnchor` 指向句子，渲染时再叠加 |

几个关键设计：

- **`Token` 记录在句子里的 UTF-16 偏移**，不用 `String.Index`。这样剧本可以序列化和缓存，点击位置也能精确对应到原文。
- **`Token.audioRange` 是词级时间戳**（来自 Whisper 强制对齐），可以支持「只重听这几个词」和卡拉 OK 式逐词高亮。
- **`TokenTag` 是开放的字符串标签**，比如 `vocab.unknown`、`list.top2000`、`exam.cet4`、`phrase.phrasal-verb`。新功能只需要新增一种标签，样式、遮挡和统计会自动按标签生效。
- **`Span` 表示跨多个 token 的片段，而且可以不连续**，用来支持 "pick *you* up" 这类被拆开的短语动词。
- **`SentenceID` 由开始时间和规范化文本生成**，所以重新生成剧本后，同一句话的 ID 不变。
- **`SentenceAnchor` = 时间区间 + 原文片段**。字幕换了版本或者重新断句后 ID 会变，收藏和笔记仍然能通过锚点找回对应的句子（已有测试覆盖）。
- **用户对剧本的修改存成编辑操作列表 `TranscriptEdit`**（调时间、拆句、并句、改字、整体偏移），由流水线最后一步重放。重新识别或重新翻译之后，用户的修改不会丢。
- **整体时间偏移只在查询时生效**，不改原始数据，所以可以随时撤销。

## 4. 剧本流水线

每个阶段实现 `TranscriptStage` 协议，带一个 `order` 排序值，在注册中心登记后自动加入流水线。用户可以在设置里关掉某个阶段。

| order | 阶段 | 状态 | 说明 |
|---|---|---|---|
| 100 | 断句 | 待实现 | 合并太短的字幕行、按标点拆开太长的行；有词级时间戳时按停顿切分 |
| 200 | `TokenizeStage` | ✅ 已实现 | NaturalLanguage 分词和词形还原（running → run），保留缩写（I'll） |
| 300 | `TimeOverlapAlignStage` | ✅ 已实现 | 中文字幕轨按时间重叠度挂到英文句子上 |
| 300 | Whisper 强制对齐 | 待实现 | 修正时间轴（网上字幕常常偏差 0.3–1 秒），并生成词级时间戳 |
| 400 | 翻译 | 待实现 | 系统 Translation 框架，或者 Claude 整集带上下文翻译 |
| 500 | `WordListTagStage` | ✅ 已实现 | 通用的词表标签：高频 2000 词、CET-4、用户熟词都用它 |
| 500 | 短语识别 | 待实现 | 短语动词和习语，生成 `Span` |
| 500 | 生词标注 | 待实现 | 根据用户的词汇状态打 `vocab.unknown` / `learning` / `known` |
| 900 | `UserEditsStage` | ✅ 已实现 | 重放用户的编辑 |

缓存键 = 媒体 ID + 原始字幕内容哈希 + 各阶段版本号。同一集第二次打开时直接读缓存，不再重新计算。

## 5. 字幕显示

### 5.1 显示层和模式

主字幕（英文）和译文各是一「层」，每层独立设置显示模式：

| 模式 | 效果 |
|---|---|
| `visible` | 正常显示 |
| `blurred` | 模糊，鼠标悬停时显示 |
| `hidden` | 完全隐藏 |
| `policy(id)` | 交给可见性策略逐词决定 |

可见性策略（`VisibilityPolicy`）逐词返回「显示 / 模糊 / 隐藏 / 挖空」。内置的 `TagVisibilityPolicy` 能覆盖大部分需求，例如：
- 只遮生词：`vocab.unknown → cloze`
- 遮住高频词来考自己：`list.top2000 → blurred`

策略还能拿到当前是第几遍播放，因此可以实现「第一遍全遮，第二遍只遮生词，第三遍全显示」这样的渐进模式。

### 5.2 样式主题

`SubtitleTheme` 包括字号、位置、译文放在上面还是下面，以及一组按标签匹配的样式规则（颜色、下划线、加粗、背景）。多条规则命中同一个词时，后面的覆盖前面的。颜色用语义名（`accent`、`warning`），由界面层解析，保证深色和浅色模式下都能看清。

### 5.3 渲染实现（界面层，M2 实现）

- 用 SwiftUI 自定义 `Layout` 做流式排版，**每个 token 是一个独立视图**。这样单词级的点击、悬停、高亮、动画都很自然。一句话只有 10–30 个 token，性能没有压力。
- 字幕视图只在**换句时**整体更新。逐词高亮只改单个 token 的状态，不重建整句。
- 侧栏的「全集剧本」列表复用同一个句子视图，当前句自动滚动到可见位置，点击某一行就跳到那一句。
- 观影模式下的 ASS 特效字幕走 libass 渲染成位图，和学习模式的文字层互不影响。

## 6. 交互：命令 + 绑定

**所有操作都是命令**（`LearningCommand`，用 `CommandID` 标识）。键盘、鼠标手势、右键菜单、命令面板（⌘K）只是触发命令的不同方式。

同一个手势作用在不同位置（`InteractionTarget`：单词、选区、句子、译文、剧本行、视频画面）时，可以绑定不同的命令。用户的自定义绑定**追加在默认绑定后面**，查找时后加的优先，所以「恢复默认」只需要清空用户绑定。

默认绑定（`Bindings.defaults`）：

| 操作 | 命令 |
|---|---|
| 单击单词 | 查词 |
| ⌥ + 单击单词 | 加入生词本 |
| 双击单词 | 只播放这个词（需要词级时间戳） |
| 拖选多个词 | 查短语 |
| 双击句子 / 单击剧本行 | 重播这一句 |
| 单击译文 | 显示 / 隐藏译文 |
| 空格 | 播放 / 暂停 |
| ← / → | 上一句 / 下一句 |
| R | 重播当前句 |
| L | 开关单句循环 |
| T | 开关译文 |
| H | 切换显示模式（全显示 → 模糊 → 隐藏） |
| S | 开始影子跟读 |
| F | 收藏这一句 |
| [ / ] | 减速 / 加速 |
| 回车 | 继续（学习程序停住等待时） |
| ⌘K | 命令面板 |

命令可以声明自己出现在哪些位置的右键菜单里，所以新命令注册后会自动出现在对应的右键菜单中。

## 7. 学习程序：循环类功能的统一模型

这是满足「各种循环、轮播、精听玩法」的关键设计。**不写死任何一种循环模式**，而是把「每一句要做什么」描述成一串步骤：

| 步骤 | 作用 |
|---|---|
| `play(rate:)` | 播放当前句，自动加上句首和句尾留白（默认提前 80ms、延后 200ms，可调） |
| `playTokens(from:to:rate:)` | 只播放句中的几个词，比如反复听一处连读 |
| `pause(seconds:)` | 停顿几秒 |
| `waitForUser` | 停住，等用户按回车继续 |
| `repeat(count:steps:)` | 重复执行一组步骤；`count` 为空表示一直重复 |
| `display(…)` | 切换字幕显示状态 |
| `record(durationFactor:)` | 跟读录音，时长 = 句子时长 × 系数 |
| `custom(id:params:)` | 扩展步骤，由注册的 `StepHandler` 执行 |

再加上一句执行完之后的行为（自动下一句 / 停住等用户 / 只处理这一句），常见功能都可以用这些步骤组合出来：

| 功能 | 步骤组合 |
|---|---|
| 单句循环 | `repeat(∞) { play, pause 0.5s }`，只处理当前句 |
| 逐句暂停 | `play`，每句结束后等用户 |
| 精听三遍 | 隐藏字幕播一遍 → 模糊字幕 0.75x 播一遍 → 显示全部再播一遍 → 等用户 |
| 影子跟读 | 显示英文 → `play` → `record ×1.3` → `play` |
| 听写 | 隐藏英文 → `play` → `custom("dictation.input")` → 显示答案 |
| 收藏句轮播（跨剧集） | 用同一个执行器，传入由收藏句组成的剧本 |

程序执行器 `PlaybackDirector` 的行为：
- 用 Swift 的结构化并发逐步执行。
- 用户按「下一句」时，取消当前任务，在新的句子上重新开始同一个程序。
- 程序结束时，把字幕显示恢复成用户原来的设置。

学习程序是 `Codable`，以 JSON 形式保存，所以以后可以做一个「自定义学习模式」编辑器，用户能自己编排、保存预设，还能分享给别人。例如内置的「精听三遍」：

```json
{
  "id": "builtin.intensive", "name": "精听三遍", "advance": "automatic", "defaultRate": 1,
  "padding": { "leadMs": 80, "trailMs": 200 },
  "steps": [
    { "display": { "_0": { "primary": { "hidden": {} }, "translation": { "hidden": {} } } } },
    { "play": {} },
    { "pause": { "seconds": 1 } },
    { "display": { "_0": { "primary": { "blurred": {} }, "translation": { "hidden": {} } } } },
    { "play": { "rate": 0.75 } },
    { "pause": { "seconds": 1 } },
    { "display": { "_0": { "primary": { "visible": {} }, "translation": { "visible": {} } } } },
    { "play": {} },
    { "waitForUser": {} }
  ]
}
```

> 注：这里是 Swift 自动生成的 JSON 格式。做成给用户编辑的格式时，会再定义一套更易读的结构。

## 8. 查词

`LookupService` 会并行查询所有已注册的 `LookupProvider`，**哪个先返回就先显示哪个**：本地词典几毫秒就出结果，大模型的语境讲解几秒后再补上，界面不用等最慢的那个。查询（`LookupQuery`）里带着整句上下文和 token 区间，支持单词和短语两种查询。

| 来源 | 优先级 | 支持短语 | 说明 |
|---|---|---|---|
| ECDICT 本地词典 | 0 | 部分 | 音标、释义、词频、考试标签 |
| 用户自定义词典 / 笔记 | 5 | 是 | 用户自己写的释义 |
| macOS 系统词典 | 10 | 是 | 系统自带的牛津词典 |
| Apple Foundation Models | 20 | 是 | 端侧大模型，结合语境讲解（需要 Apple Silicon + macOS 26） |
| Claude | 30 | 是 | 云端，讲解质量最好，用户自己提供 API Key |

## 9. 学习事件

所有学习行为都会发一条 `LearningEvent`（开始一句、播了一遍、查了词、收藏、录音得分、程序结束，以及自定义事件），并写入数据库形成流水。以后要加的这类功能，都只需要「从流水里算」，不需要回头改埋点：
- 今天听了多少句、精听了多久
- 查过三次的词自动加入生词本
- 根据生词密度推荐难度合适的剧集
- FSRS 复习计划

## 10. 扩展点一览：以后加功能怎么接

| 想加的功能 | 用到的扩展点 | 需要改核心代码吗 |
|---|---|---|
| 新的字幕来源（OpenSubtitles、射手网） | `SubtitleSource` | 否 |
| 标出 CET-6 / 雅思词汇 | `WordListTagStage` 加一份词表，再加一条主题样式规则 | 否 |
| 识别短语动词和习语 | 新增一个 `TranscriptStage`，生成 `Span` | 否 |
| 识别说话人（给每句标上角色名） | 新增一个 `TranscriptStage`，写入 `Sentence.speaker` | 否 |
| 听写模式 | `StepHandler`（输入框和比对）+ 新的 `LearningProgram` | 否 |
| 只遮生词 / 渐进式遮挡 | `VisibilityPolicy` | 否 |
| 换一个词典 | `LookupProvider` | 否 |
| 导出 Anki / 导出带时间轴的句子音频 | `LearningCommand`（加入右键菜单） | 否 |
| 连读、弱读标注 | `TranscriptStage` 打标签 + 主题样式规则 | 否 |
| AI 问答（「这句为什么用过去完成时」） | `LearningCommand` + 侧栏面板 | 否 |
| 学习统计面板 | 订阅 `EventBus` + 侧栏面板 | 否 |
| 用户写脚本扩展（类似 IINA 插件） | 把 `ExtensionRegistry` 桥接到 JavaScriptCore | 只需加一个桥接层 |

> 侧栏面板（SwiftUI 视图）属于界面层，到时候会在 App 里加一个面板注册中心。`LearningCore` 本身不依赖任何界面框架，所以可以单独测试。

## 11. 存储（M2 实现，SQLiteData / GRDB）

| 表 | 内容 |
|---|---|
| `transcript_cache` | 媒体 ID + 内容哈希 → 压缩后的剧本 JSON（不按 token 拆行存储，读写更快） |
| `transcript_edits` | 媒体 ID → `TranscriptEdit` 列表 |
| `vocabulary` | 单词原形、状态（生词 / 学习中 / 熟词）、FSRS 参数、首次遇到的时间 |
| `vocabulary_examples` | 单词 → `SentenceAnchor`，可以附带截图和音频片段的路径 |
| `saved_sentences` | `SentenceAnchor`、笔记、标签 |
| `events` | 时间戳、事件 JSON |
| `programs` / `themes` / `bindings` | 用户自定义的学习程序、主题、快捷键（JSON） |
| `settings` | 分层配置：全局 → 剧集 → 单集（比如某一集单独的字幕偏移） |
